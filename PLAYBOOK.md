# Personal project workflow

## Start and recover
Read POLICY.md, your role, and ~/vaults/Personal/Bridge.md, Board.md and Implementation-queue.md. Verify repository state before resuming work. Saved pane labels do not grant an assignment.

## Execute
1. Capture the outcome, scope, repository, acceptance criteria and authorized delivery steps in a brief.
2. Inspect the existing project and resolve consequential assumptions before implementation.
3. For delegated work, use an implementation lead to coordinate builders in isolated worktrees. Give each worker a self-contained brief and report path.
4. Implement the smallest complete solution and run relevant existing checks.
5. Use an independent reviewer for substantial changes when delegation is authorized. Give the reviewer the requirements and evidence, without relying on the builder's conclusions.
6. Resolve material findings, complete authorized delivery steps, and verify the resulting behavior.
7. Update the project note, queue and Bridge. Record remaining work explicitly.

## Evidence and communication
Report what changed, why, what was verified and any remaining limits. Distinguish observed facts from assumptions. Keep routine coordination in reports and the queue. Bring the user concrete outcomes, necessary decisions and actual blockers.

## Notes
Project notes hold current state and next actions; briefs hold assignments; reports hold evidence; the queue holds ownership and ordering. Replace stale summaries rather than accumulating conflicting current states.
